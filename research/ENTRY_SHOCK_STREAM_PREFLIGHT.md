# Continuous entry-shock input preflight

This follows `ENTRY_SHOCK_CONTINUOUS_FREEZE.md`. It is an input-supply feasibility check for that unchanged candidate, not another strategy screen. Only public object metadata and one capped 10 MB public transfer pilot were fetched; no complete corpus or continuous wallet was run.

## Original contract recovered

The original full account's archived registration is `c6223a5...:backtest-source/coin-registration.json`. Its byte SHA-256 is the full receipt's exact specification SHA. Its 795-start schedule also matches the receipt byte-for-byte. All **18** original `coinquant` runtime files from head `47837e3...` and all **nine** archived research/venue files match their per-file receipt SHA. The later quarter runner has 11 changed runtime files and four added files; its outcome is not an original full-path baseline. A task-owned extracted original source tree is at `/workspace/coinquant-original-source`; this is a local verification copy, not `main`.

The already restored original four-hour/funding market produces the exact archived market-identity and market-values digests. The archived FX file matches the full receipt's FX SHA. The original ALFRED packets yield the same macro-history digest and 1,914 dated vintages. Rules and public warmup packets were restored from that same archive. Thus the missing execution bodies, not the model history, are the material input gap.

The original `TradePrints` checks each official daily ZIP against its `.CHECKSUM` before parsing and holds one day of rows. `Market` loads one-minute trade/mark months on demand. The original `data_loader` uses its prior-content shortcut only when exact file metadata and sidecar text match; a new task-owned body is fully hashed. The driver snapshots every market/print sidecar path and text at segment start and rejects changes at segment end. A rolling supply must therefore install its complete fixed sidecar set **before** the first segment, keep it immutable, and rotate only fully verified task-owned ZIP bodies **between safe segments**. This changes the input-path/sidecar binding from the archived run, even if the economic bytes are equal. A fresh baseline is required; its complete output must agree with the archived baseline before a candidate comparison is accepted.

## Targeted equivalence already checked

- Using the original restored parser and original `data_loader`, two fixed public print days matched the SHA, four packed integer columns and loaded hashes in a task-owned copied source. Original one-minute trade/mark tables were equal. Removing only the task-owned older body left the sidecar snapshot unchanged and did not affect the next-day read.
- A separate fixed public three-day month-boundary read gave identical `last` and `raw` results before and after retiring the day older than the previous day. This checks the loader's one-day backward query; it does not claim every future access pattern is proved.
- One necessary saved **2020Q1 offline baseline** was rerun with all 91 fixed public print bodies copied to a task-owned location and verified against their official sidecars. All 33 original manual sessions completed in 47 seconds. The original and copied-source wallets matched **29 economic/account fields exactly**, including every trade, funding entry, fee, daily path, final CNY, MDD, loaded input hash, audit and session count. Only input identity and elapsed wall time differed. The short wallet's 26 trades, 92 daily path points and 33 loaded print hashes also equal the corresponding prefix of the archived original complete wallet. This proves source relocation and byte-equivalent loading for that short wallet; it is not a continuous baseline, an intra-run eviction test or native execution evidence.
- An additional **five-session original-source checkpoint probe** used the restored 18 runtime and nine tooling files, the original `data_loader` and `replay_checkpoint`, two independent task-owned SQLite wallets, and the original first five manual starts. One wallet ran uninterrupted. The other snapshotted at a verified third-session boundary, retired only a task-owned older print body while retaining sidecars, constructed a fresh offline venue, restored against the *same durable SQLite*, and ran the remaining two starts. Their venue financial/account/order/daily/source-hash digest matched exactly. This proves the original checkpoint codec and a short source-retirement continuation; it does not yet prove the external `SIGTERM` supervisor over the full path.
- The **original archived full-account driver** was then exercised for a short prefix with its SHA-verified runtime/tooling bytes. A local wrapper changed only its hardcoded Git-root admission to point at the separately restored source tree; the original financial driver and checkpoint implementation were not edited. The derived input spec retained the original 795-start schedule and source fingerprint but used task-owned print paths, so its input binding correctly differed. A journal watcher sent `SIGTERM` after complete sessions; the first segment stopped safely after four starts, its bound checkpoint and SQLite passed, a task-owned old print body was removed with all sidecars unchanged, and resume stopped safely after three more starts. **All fields of all seven resulting session reports exactly match** the archived original complete account's corresponding prefix. This proves the short driver-level signal/checkpoint/restore path as well as the original market/decision outputs; it does not justify skipping the fresh full baseline under the changed input binding.

## Smallest unchanged-model supply route

1. Before either full wallet, build the fixed **public calendar** sidecar set for every daily USD-M `aggTrades` ZIP from 2020-01-01 through 2026-09-19 and all required original one-minute/market files. The archived receipt and four saved public quarters already provide sidecars for 1,047 of these 2,454 in-range days; at most **1,407** additional public-day sidecars are missing. Query a fixed calendar list, never the archived session-selected day list. Retain official SHA/size and check each new ZIP fully before atomic publication to a task-owned root. No order IDs, manual starts or account dates enter external requests.
2. Restore missing one-minute files from official public sources against archived SHA wherever known. Keep all one-minute, four-hour and funding files available throughout a run; the original one-minute set was only 0.224 GiB compressed. Preserve the original daily one-minute overrides, especially the terminal month. Do not substitute monthly trade prints for the producer's daily files.
3. Stage a fixed calendar quarter plus the **next** quarter of print ZIPs before starting a segment. Baseline and candidate each run serially through the first manual session in the next quarter, then receive `SIGTERM`; the original driver stops only at a completed session and writes a bound checkpoint. A local journal watcher observes that fixed quarter boundary but does not change a session, model, order or exchange time. The extra quarter is a margin for signal delivery. Verify `can_resume`, checkpoint/SQLite/report SHA, settled orders and protection before rotating bodies. Never delete during an active segment. Keep the previous complete day plus current/next quarters, then prune only this task's older copied ZIPs; sidecars remain. Resume both wallets on the original 795 starts. The schedule's largest interval between manual starts is 6.29 days; the calendar-quarter margin is much larger. Missing prints still mark the path unknown and invalidate the wallet; no missing file may be treated as an empty market.
4. The original driver accepts `max_segments` from its specification and checks source/spec bindings on resume. A derived research specification needs at least 30 segments for roughly 27 fixed-quarter boundaries; both wallets must use the same immutable input/FX/schedule specification. This changes the spec SHA, so the archived baseline cannot be reused under the strict old binding. The runtime checkout must use the exact original 18 files and nine tooling files, with the candidate's sole frozen gate explicitly included in its research binding. The original driver hardcodes `/workspace/coinquant` and its Git head; staging the source in another folder alone does not satisfy that guard. A reversible isolated execution arrangement is still required, and may not relabel a patched producer as the original.

The source calendar needs **2,090** more print ZIP bodies than the four saved quarters, plus **186** archived one-minute bodies missing here. The original 660 missing selected print bodies alone were 11.666 GiB; a candidate may need other days. An **81-month fixed public S3 listing** was read without downloading ZIP bodies. It confirms all 2,454 in-range daily objects, **41.584 GiB** total compressed, with no size change among the 773 original used print objects. The largest current listed day is **0.104 GiB**, quarter **3.124 GiB**, and adjacent two-quarter window **5.446 GiB**. These are actual current public object-size metadata, not historical first-publication evidence or a promise that the remote objects will remain unchanged. The four saved full quarters contain 5.521 GiB, leaving about **36.063 GiB** of bodies to transfer if the complete fixed calendar is staged once. Current workspace free space after the short check is about **26.3 GiB**. A fixed quarter plus the next quarter and one previous day currently peaks below **5.55 GiB** of print ZIP bodies; recheck object sizes/official SHA immediately before each transfer. Set a hard **16 GiB** ceiling on task-owned staged print ZIPs and keep at least **8 GiB** workspace free for state, parsed arrays and checkpoints; stop before transfer if a window breaches either limit. These are resource stop conditions, not strategy parameters. A day whose uncompressed parser memory exceeds available memory also stops. No existing raw evidence or user directory is deleted.

The prior uninterrupted full wallet needed 2,423 seconds after inputs were present. Its original registered compute ceiling is 7,200 seconds; one fresh baseline plus one candidate therefore have an absolute registered **14,400-second compute budget** before input acquisition, with extra segment-start overhead. A capped fixed-public-day ZIP pilot transferred **10,064,410 bytes** and passed the official SHA in **1.49 seconds** (6.43 MiB/s). At that single observed rate, 36.063 GiB would take roughly **96 minutes** serially; this is a planning estimate, **not a network-time upper bound**. The execution supervisor should impose a **six-hour cumulative public transfer timeout** (including retries) and a **12-hour overall execution stop budget**, counting transfer, setup, both wallets and audit. Those are fail-closed spending limits, not a promise of completion or an economic criterion; they must be implemented before the large restore. This preflight stops before the 36 GiB public-body restore or either 795-session run. The nominal pair alone still cannot satisfy the separately frozen doubled-cost/native adoption gates.

## Remaining execution gates

Before the large restore, turn the proven short journal-watcher sequence into a bounded quarter-level supervisor: stage the current and next fixed public quarters, require immutable sidecars, stop only after completed-session reports, assert the original checkpoint/SQLite/report binding, and prune only task-owned older bodies while both wallets are stopped. Its observed signal delay was one extra session in each short segment, safely inside the next-quarter buffer; a full supervisor must fail closed if its watcher dies. The original driver's hardcoded source-root/head guard needs an isolated, reversible checkout arrangement or an explicitly labelled extracted-source admission wrapper; any research wrapper around the one candidate decision must have its own source/rule hash and must not be labelled as the original producer. Re-run the fresh continuous baseline once only after these gates and the fixed public source bodies are ready. Reject it if its prefix and final economics do not reproduce the archived original account. The already authorized research scope covers these local preparations; the broad 36 GiB public restore and long paired run were intentionally not initiated in this preflight and should be reviewed as that concrete next action. No Demo/live account, credential, deployment or strategy-main action is involved.
