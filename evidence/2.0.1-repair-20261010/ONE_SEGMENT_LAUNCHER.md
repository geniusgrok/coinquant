# 外部进程中断后的逐段启动

首个 margin-only 完整运行在已写 788 条会话报告后失去后台进程，最后 segment003 没有回执。检查时原 exec session ID 返回 Unknown process id，日志和报告停留数分钟不再更新；不能证明中断的具体宿主原因。原账户、日志、两个已完成分段回执和检查点全部保留，记为未完成，未发布任何部分年化。

由于原始报告和 SQLite 已前进到最后安全分段之后，原回放器的严格恢复条件不允许截断报告或回滚账户。因此新建 margin-only-rerun-001 从零完整复测；case 仍为 margin-only，公开源码与所有经济设置不变，新 spec 单独登记输出身份。

为控制单个外部后台任务生命周期，后续由 run_one_segment.py 每次只启动原定一个最多 540 秒的分段。它从未修改的 run_pair.py 派生，只在写完进度后返回，并将终端提示改为 segment_finished_arm；源码/输入准入、原 driver、参数、回执、正常账户锁、检查点和恢复检查均沿用原程序。原 run_pair.py 字节原样保存，实际调用命令和这个 launcher 的 SHA 逐段写入 FULL_COMMANDS.jsonl。

每次待上一个进程结束并验证分段回执后，再启动下一个。同一离线 UID 12000 从不并行执行账户会话。先完成组合 v2，再完成盘口 v2 和保证金重试，所有完整指标仍须独立 full795 审计通过。
